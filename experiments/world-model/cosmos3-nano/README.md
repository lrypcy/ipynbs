# Cosmos 3 Nano：把「16B」拆成五笔可加的账

对应文章：《Cosmos 3 Nano：16B 里只有 8B 在干活》，
<https://lrypcy.github.io/2026/11/05/cosmos3-nano-dual-tower-accounting/>

技术报告：NVIDIA, *Cosmos 3: Omnimodal World Models for Physical AI*（2026-06-22，139 页），
<https://research.nvidia.com/labs/cosmos-lab/cosmos3/technical-report.pdf>

Cosmos 3 用一套权重同时做四件事：当 VLM 推理、当视频生成器、当世界模拟器、当
世界动作模型（WAM）。这件事在参数表上留下的痕迹是：**一个 16B 的模型，单塔只有 8B**。
本实验把这句看起来像营销话术的话拆成可以逐位对账的五笔账。

**A–F 是从论文超参与公式重算**（可复现）；**G、H 用的是论文表格里的读数**
（Table 18 / 20 / 31、Fig. 28 / 29），只做换算与结构分析，不重跑模型。

## 怎么跑

```bash
~/Software/miniconda3/bin/python cosmos3_lab.py       # 约 2 秒，63 条断言
~/Software/miniconda3/bin/python cosmos3_figures.py   # 出 6 张图
```

`cosmos3_lab.ipynb` 是同一份代码（按 `# %%` 切成 10 个 cell），输出已固化在文件里，
不必执行。`results/stdout.txt` 是 `python cosmos3_lab.py` 的完整输出，正文里的数字与它逐位对齐。

## 一个必须说清的前提

C 组里 256p 那一格算得 B=25 而报告写 B=6。报告的表 9 把它归因于「74K 上下文」，
但 6 个 256p 样本只占 17,280 token。所以短序列一侧的约束**不是** token 预算，
更可能是显存或 kernel 启动开销。本实验不臆测原因，只标出这一格对不上——
把「所有边界都由上下文决定」当成结论会读错。

D 组里 15000 这个间隔折算成 2500 秒，远超任何训练片段。它只能被理解成**位置缓冲**
（把文本末 token 与首帧 token 的位置嵌入拉开），不能读成物理时间。
