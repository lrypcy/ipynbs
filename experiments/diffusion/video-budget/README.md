# video-budget：视频扩散的 token 预算与注意力账本

对应文章：[扩散模型的 token 预算：视频为什么贵，贵在哪一条轴上](https://lrypcy.github.io/2026/11/02/diffusion-video-token/)

## 要验证的论断

| 组 | 论断 |
| --- | --- |
| A | token 数 $$N=n_t n_h n_w$$ 对帧数与分辨率线性、对 patch 边长平方反比；整除截断会让「边长翻倍 ⇒ 1/4」在 720p 上变成 **0.2444** |
| B | 时空分解 / 全 3D $$=1/n_t+1/n_{hw}$$（**不是** $$1/n_t+1/n_t^2$$）；分解后时间项只占空间项的 $$n_t/n_{hw}$$，720p/96 帧时 **0.67%** |
| B | 因果结构相对双向采样只省 **1.920×**（上界 2×）；而 KV cache 在 query-key **对数上省 0**，它省的是 K/V 投影，倍数 $$d(n_t+1)/2$$ = **50×** |
| C | 训练与采样**同为平方**（斜率 2.000 / 1.950），差别只落在常数上：训练/采样 → $$2/d$$；$$d\ge2$$ 时采样一遍就比训练一遍贵 |
| D | 3D VAE 的 $$f_t$$ 压缩与空间压缩在 token 账本上等价（345600 = 345600），但 $$f_t$$ 的收益在平方项上被放大一次（成本降到 1/16） |
| E | 固定预算下最大边长 $$\propto T^{-1/2}$$；同预算同 720p，全 3D 只撑 25 秒、分解撑 21 分钟（49×）；720p→1080p 时长比正好 2.25 |

## 运行

```bash
python video_budget_lab.py                 # 全部 A–E，约 0.4 秒
python video_budget_lab.py B E             # 只跑指定组
python video_budget_lab.py --figdir DIR    # 额外画两张图
```

### 为什么这一篇没有采样实验

前四篇（采样器数值、后训练、少步生成、块扩散）都要跑随机过程，因为要测的是
「误差如何随步数 / 组大小兑现」。这一篇测的是**账本**：query-key 对数、K/V 投影次数、
token 数。这些量是整数计数，有闭式，跑采样只会往里塞噪声。

代价是它更难被推翻，所以每一笔都同时给**闭式 + 逐项求和的实测值**，断言的是
`abs(measured - closed_form) < 1e-12`，而不是「看起来差不多」。想推翻它，只需要指出
某个求和式不该长这样——比如把时空分解的时间项写成 $$n_{hw}n_t$$（那就成了逐帧独立的 2D 扩散），
B 组第一条断言立刻报错。

### 三处不能省的细节

1. **整除截断不是小数点后的事**。`shape()` 用 `H // (fs*p)`：720p、patch 2→4 时
   $$n_h$$ 是 45→22（不是 22.5），于是 token 数比值是 0.2444 而不是 0.25。
   先把账本按整除算清楚，再谈「1/4」；否则所有成本数字都会系统性偏乐观 2.2%。
2. **分解的闭式要自己推一遍**。空间项 $$n_t n_{hw}^2$$、时间项 $$n_{hw}n_t^2$$，
   各自除掉 $$N^2=n_t^2n_{hw}^2$$ 之后得到的是 $$1/n_t$$ 与 $$1/n_{hw}$$——
   两项的分母**不同**。写成 $$1/n_t+1/n_t^2$$ 会得出「分解比与分辨率无关」的错误结论。
3. **KV cache 在 query-key 对数上的收益是 0**。因果采样第 $$t$$ 帧的对数是
   $$d\cdot n_{hw}\cdot(t+1)n_{hw}$$，缓存与否这个求和式一模一样：
   cache 剪掉的是**重复的 K/V 投影**（$$d(n_t+1)/2$$ 倍），不是重复的配对。
   把两笔账混起来，就会得到「KV cache 有 $$n_t$$ 倍加速」这种既不真也没用的说法。

## 四条结论

1. **账本对三个旋钮是线性的，只对 patch 平方反比**。真正把「视频贵」放大的是后面那一步：
   $$N$$ 翻倍 ⇒ attention 对数翻四倍。帧数、分辨率、patch 在这条链上的地位完全不同。
2. **分解比是 $$1/n_t+1/n_{hw}$$，两项分母不同**。720p 上空间项占 99.3%，
   时间注意力只值 0.67%——所谓「视频建模难」在算力上根本不是跨帧注意力造成的。
3. **因果只省 2×，cache 省 $$d(n_t+1)/2$$，两笔账别混**。因果结构把平均 key 数砍半，
   对数账本上省 1.92×；KV cache 一对不省，它省的是重复投影（50×）。混着谈就会得出
   「KV cache 有 $$n_t$$ 倍加速」。
4. **$$d$$ 是唯一能把整条账翻过来的旋钮**。$$d<2n_t/(n_t+1)\approx1.92$$ 时采样一遍比训练一遍便宜，
   $$d\ge2$$ 就贵。训练/采样 → $$2/d$$，与分辨率、与 clip 长度都无关——
   所以视频生成提速的全部功夫都压在「少步」上，这也正是少步生成那一篇的位置。
