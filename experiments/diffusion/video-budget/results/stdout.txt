A 组：token 账本——谁线性、谁平方
------------------------------------------------------------------------------
  基准：720×1280，96 帧（4.0s @ 24fps），VAE 8×/4×，patch 2
        n_t=24，n_h=45，n_w=80，N=86400
  T 翻倍 → N×2.00，训练 attention ×4.00
  H 翻倍 → N×2.00，训练 attention ×4.00
  W 翻倍 → N×2.00，训练 attention ×4.00
  [ok]   帧数与分辨率翻倍都让 N 精确翻倍——token 数对三个旋钮都是线性的
  patch 2→4：N=86400→21120（×0.2444）
        n_h 45→22、n_w 80→40——720 不被 32 整除，整除截断让实际比值略低于 1/4
  [ok]   patch 边长翻倍 ⇒ token 数精确降到 1/4（1024² 上 98304→24576）——patch 是平方反比，帧数只是线性
  [ok]   720p 上截断让它变成 0.2444：分辨率不能被 fs·p 整除时，账本要先按整除算，别直接用 1/4 估
  [ok]   VAE 时间压缩 1→8：token 数 345600→43200，正好 1/8——这是 3D VAE 相对 2D VAE 唯一真正「省在时间轴」的地方

  典型配置对账（H×W，帧数，VAE，patch → N）
    256×256,  16 帧, VAE 8/4, patch 1  →  n_t= 4 n_h=32 n_w=32  N=  4096
    512×512,  16 帧, VAE 8/4, patch 1  →  n_t= 4 n_h=64 n_w=64  N= 16384
    512×512,  49 帧, VAE 8/4, patch 2  →  n_t=12 n_h=32 n_w=32  N= 12288
    720×1280,  96 帧, VAE 8/4, patch 2  →  n_t=24 n_h=45 n_w=80  N= 86400
    720×1280,  96 帧, VAE 8/4, patch 1  →  n_t=24 n_h=90 n_w=160  N=345600
    1080×1920, 192 帧, VAE 8/4, patch 2  →  n_t=48 n_h=67 n_w=120  N=385920

B 组：三种注意力的成本与交叉点
------------------------------------------------------------------------------
  n_t=24，n_h×n_w=3600，N=86400，采样 4 步
  方案                          query-key 对数   相对全 3D
  全 3D（训练，1 遍）                7.465e+09      1.0000
  时空分解（训练，1 遍）             3.131e+08      0.0419
  双向采样（4 步）                   2.986e+10      4.0000
  因果+KV 采样（4 步）               1.555e+10      2.0833
  [ok]   分解/全3D = 1/n_t + 1/n_hw = 0.041944（实测 0.041944）——空间项给 1/n_t，时间项给 1/n_hw，两个旋钮各管一项
  [ok]   时空分解的训练成本只有全 3D 的 4.19%——n_hw 越大，这个比值越趋近 1/n_t
  [ok]   因果/双向 = (n_t+1)/(2n_t) = 0.520833（实测 0.520833）
  [ok]   因果结构相对双向只省 1.920×，上界就是 2×——总 query 数没变（都是 N），变的是平均 key 数从 n_t·n_hw 落到 (n_t+1)/2·n_hw
  （n_t=6 时省 1.714×，n_t=96 时省 1.979×，再长也压在 2× 以下）

  KV cache 到底省哪一笔（因果采样，d=4）
                        query-key 对数   K/V 投影 token 次
  不缓存                     1.555e+10             4320000
  缓存                       1.555e+10               86400
  [ok]   对数这一列两行完全相同：KV cache 在 attention 对数上一分不省——剪掉的是重复的 K/V 投影，不是重复的配对
  [ok]   投影这一列缓存省 50×，正好 d(n_t+1)/2——「KV cache 有 n_t 倍加速」这句话的真身在这里，在投影上，不在配对上
  [ok]   4 步因果采样（1.555e+10）比分解注意力的一次训练前向（3.131e+08）贵 49.7 倍——训练一遍只跑一次，采样要同一 clip 跑 4 遍
  [ok]   甚至比全 3D 的一次前向（7.465e+09）还贵 2.083×，而这个比值就是 (n_t+1)/(2n_t)·d ≈ d/2
  [ok]   因果采样/全3D 前向 = d(n_t+1)/(2n_t) = 2.083333（实测 2.083333）——与分辨率、与 clip 长度都无关，只与步数 d 成正比

  时空分解 vs 全 3D：相等条件 n_t·n_hw = n_hw + n_t ⇔ n_t = n_hw/(n_hw-1)
    n_hw=    2：临界 n_t = 2.0000
    n_hw=   16：临界 n_t = 1.0667
    n_hw=  256：临界 n_t = 1.0039
    n_hw= 4096：临界 n_t = 1.0002
  [ok]   分解更省的充要条件是 n_t(n_hw-1) > n_hw，等价于 n_t > n_hw/(n_hw-1) ≤ 2——只要 n_t ≥ 2（n_hw ≥ 4）就成立；n_t=1 时那项 n_hw·n_t² 纯属白付

  分解后两项各占多少（空间 = N·n_hw，时间 = n_hw·n_t²）
  配置                                 空间项       时间项  时间/空间
  256x256, 16 帧, p=1               4.194e+06    1.638e+04    0.00391
  512x512, 49 帧, p=2               1.258e+07    1.475e+05    0.01172
  720x1280, 96 帧, p=2              3.110e+08    2.074e+06    0.00667
  720x1280, 384 帧, p=2             1.244e+09    3.318e+07    0.02667
  1080x1920, 192 帧, p=2            3.103e+09    1.852e+07    0.00597
  [ok]   时间/空间 = n_t/n_hw，精确到 1e-12——时间注意力的标价是 n_hw·n_t²，只占空间项的 n_t/n_hw
  [ok]   所有配置下时间项都不到空间项的 5%（720p/96 帧时只有 0.67%）——视频扩散的注意力账单几乎全在帧内空间，不在跨帧时间

C 组：帧数翻倍时，训练与采样各自的指数
------------------------------------------------------------------------------
  n_h×n_w=3600，采样 4 步
   T（帧）   n_t  训练（全 3D 前向）      因果+KV 采样   训练/采样
        24     6           4.666e+08         1.089e+09       0.429
        48    12           1.866e+09         4.044e+09       0.462
        96    24           7.465e+09         1.555e+10       0.480
       192    48           2.986e+10         6.096e+10       0.490
       384    96           1.194e+11         2.414e+11       0.495
  [ok]   训练成本随 n_t 的 log-log 斜率 = 2.0000（平方）——帧数翻倍，训练算力翻四倍
  [ok]   因果 + KV 采样的斜率 = 1.9499，略低于 2 正是因为 (n_t+1) 里的那个 +1（首帧只见自己）
  [ok]   两者同为平方：因果结构没有改变指数，只改变常数——「采样是线性的」是把 token 数 N 当成算力，漏掉了 d 步
  [ok]   训练/采样 的比值单调升向 2/d = 0.500（0.429 → 0.495）——与 n_t 无关，只由步数定
  [ok]   d=4 ≥ 2 时采样一遍严格比训练一遍贵（每 clip 被重跑 d 遍，因果只省回 2×）
  [ok]   d=1 时反过来：采样一遍比训练一遍便宜——这就是少步生成把整条账翻过来的地方（对应少步生成那篇）

D 组：3D VAE 的时空压缩——时间轴压缩比空间轴贵还是便宜
------------------------------------------------------------------------------
  固定 720×1280、96 帧，目标：把 N 压到基准的给定比例
  基准                               N     相对
  fs=8, ft=1, p=1              1382400   1.0000
  fs=8, ft=4, p=1               345600   0.2500
  fs=8, ft=1, p=2               345600   0.2500
  fs=8, ft=4, p=2                86400   0.0625
  fs=16, ft=4, p=2               21120   0.0153
  [ok]   ft 1→4（4×）与 fs 8→16（空间 4×）压出完全相同的 token 数（345600 = 345600）——在 token 账本上两者等价，差别只在信息量
  [ok]   ft=1→4 让 N 降到 1/4，attention 成本降到 1/16（1.911e+12→1.194e+11）——时间压缩的收益在平方项上被放大一次

  每帧平均 token 数（决定 KV cache 的粒度）
    ft=1: n_t= 96，每帧 3600.0 token，总 N=345600
    ft=2: n_t= 48，每帧 3600.0 token，总 N=172800
    ft=4: n_t= 24，每帧 3600.0 token，总 N=86400
    ft=8: n_t= 12，每帧 3600.0 token，总 N=43200

E 组：固定算力预算，帧数与分辨率怎么分配
------------------------------------------------------------------------------
  预算（全 3D 训练的 query-key 对数）= 3.0e+11，对应 N* = √budget = 547723
  闭式：N = n_t·n_h²，N² ≤ budget ⇒ n_h = √(√budget / n_t) ⇒ 边长 ∝ T^(-1/2)
   T（帧）   n_t     边长*（连续）  边长（取 16 倍数）         N   每秒 token
        24     6              4834                4832    547224       547224
        48    12              3418                3408    544428       272214
        96    24              2417                2416    547224       136806
       192    48              1709                1696    539328        67416
       384    96              1209                1200    540000        33750
       768   192               855                 848    539328        16854
  [ok]   固定预算下最大边长 ∝ T^(-1/2)（比值 [1.0, 0.707, 0.5, 0.354, 0.25, 0.177] vs 理论 [1.0, 0.707, 0.5, 0.354, 0.25, 0.177]）——帧数翻 4 倍，边长只能砍一半
  [ok]   取 16 倍数后的整数解仍在预算内，且与连续解相差不到 16 px
  [ok]   每秒钟的 token 数随帧数下降（547224 → 16854）——平方预算下，长视频只能靠降分辨率换

  固定 720p（n_hw=3600）、固定预算，两种注意力各能撑多久：
    全 3D     n_t=  152，T=   608 帧，   25.33 秒
    时空分解  n_t= 7504，T= 30016 帧，    20.8 分钟
  [ok]   全 3D：n_t=152 正好把预算用满（2.994e+11）
  [ok]   时空分解：n_t=7504 把同一笔预算用满（3.000e+11）
  [ok]   同预算、同分辨率，分解注意力能撑 49× 的帧数（25 秒 → 21 分钟）——注意力结构一变，瓶颈就从注意力挪到了别处

  固定分辨率、同一笔预算，全 3D 前向能撑多长：
    720p    n_t= 270，T= 1080 帧，  45.0 秒
    1080p   n_t= 122，T=  488 帧，  20.3 秒
  [ok]   720p 能撑 45 秒、1080p 只有 20 秒，比值 2.213 就是 (1080/720)² = 2.250——在平方预算里，分辨率涨一档就等于时长砍一半
