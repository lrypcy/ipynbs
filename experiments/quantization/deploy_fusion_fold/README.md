## 实验内容

- **第 0 组｜执行层前提**：确认「QDQ 图可导出」与「整数 kernel 会执行」是两件事。
  三条独立证据：底层量化原语可用；裸 `nn.Linear` 的 `quantize_dynamic` **静默返回浮点模型**；
  嵌套在 `Sequential` 里的 `Linear` 直接抛 `NoQEngine`。
- **A 组｜融合恒等式**：验证 `s_W s_x[q_W q_x - z_x·rowsum(W) - z_W·sum(x) + K·z_W·z_x]`
  与「先反量化再做浮点 GEMM」**逐位一致**。
- **B 组｜三项修正的消融**：逐项拆掉，看误差放大多少倍。
- **C 组｜对称量化为什么工程上更省**：`z_W = 0` 时哪两项自动归零、代价是多少 dB。
- **D 组｜requantize 的定点乘子**：`M0` 的位宽够不够、三种舍入口径哪个有偏。
- **E 组｜三笔收益账**：算力 / 带宽 / 显存分开算，回答 W4A16 的 4× 到底来自哪一笔。
- **E5 组｜融合本身省什么**：三项修正的算术占比 vs 融合省下的 HBM 流量。

## 关键数字（SEED=0，full 模式实测）

**B 组｜三项修正的消融**（相对完整表达式）

| 变体 | max err | 相对误差 |
|---|---|---|
| 完整三项 | 8.882e-16 | 0.0000 |
| 去掉 `z_x·rowsum(W)` | 3.761e+01 | 8.8272 |
| 去掉 `z_W·sum(x)` | 2.538e+01 | 5.9570 |
| 去掉 `K·z_W·z_x` | 2.634e+01 | 6.1827 |
| 裸整数 GEMM | 3.665e+01 | 8.6015 |

**C 组**：对称权重下 `term_W` 与 `term_c` 自动归零；`term_x` 仍 127/128 项非零。
代价是权重重构 SNR 从 40.31 dB 降到 39.45 dB（**−0.86 dB**，本探针是零均值 randn，真实偏置权重下差值更大）。

**D 组**：`M0 = 1260697305`（在 int32 正数域内），`shift = 39`；
`M0·acc` 峰值 7.64e+13 需 **48 bit** → 必须用 int64 累加。
M0 位宽扫描：8 位时 6.250% 码字不一致，≥12 位起逐位一致。

**D 组｜三种舍入口径**（有符号均值，无偏应 ≈ 0）

| 写法 | 有符号均值 | max abs err | 判定 |
|---|---|---|---|
| 裸右移 `v>>sh` | −0.49933 | 1.000 | **有偏** |
| 加半右移 `(v+2^{sh-1})>>sh` | −0.00084 | 0.500 | 无偏 |
| 对称加半右移 | −0.00084 | 0.500 | 无偏 |

**E 组｜M=1（decode）算术强度闭式 16/b_W 校验**

| 格式 | AI | 16/b_W | 相对偏差 |
|---|---|---|---|
| FP16 | 0.9995 | 1.0000 | 0.0488% |
| W8A8 | 1.9990 | 2.0000 | 0.0488% |
| W4A16 | 3.9922 | 4.0000 | 0.1949% |
| W4A8 | 3.9961 | 4.0000 | 0.0976% |

**E5｜融合的收益结构（N=K=4096，W4A16，M=1，闭式记账）**

| 路径 | 权重侧 | 激活侧 | 合计 |
|---|---|---|---|
| 不融合 | 8.39 读 + 33.55 写 + 33.55 再读 = 75.50 MB | 0.02 MB | 75.52 MB |
| 融合 | 8.39 MB | 0.01 MB | 8.40 MB |

流量比 **8.994x**（省 88.9%）。省下的 67.11 MB 来自「不再搬运 fp16 权重」，是融合后总流量的 7.99 倍。
对照：三项修正的算术量 8193 次，仅占 GEMM 的 **0.0488%** —— **融合几乎不省算术**。

**E3｜权重位宽与激活位宽的收益方向相反**

| M | 只动激活（W4A16→W4A8） | 只动权重（W8A8→W4A8） |
|---|---|---|
| 1 | 1.0010x | 1.9990x |
| 8 | 1.0078x | 1.9922x |
| 64 | 1.0588x | 1.9412x |
| 512 | 1.3333x | 1.6667x |
| 4096 | 1.8000x | 1.2000x |

## 两条被推翻的初始判断（写完即更正）

1. **「加半再右移对负数有 −0.5 偏置」是错的。** 初稿曾据此写结论，逐样本复核发现
   那个 −0.5 来自自写的 `divmod` 负数分支 bug（`//` 是 floor 语义）。
   严格检验下 `(v+2^{sh-1})>>sh` 的无符号均值 0.500、有符号均值 ≈ 0 —— 因为
   `floor(y+0.5)` 对正负一致地给出 round-half-up。**真正有偏的是不带加半的裸右移。**
2. **「参考值要用精确有理数」。** 用 `ratio * a` 当参考时，`ratio` 的 ~1e-10 相对误差
   在 `|a| ~ 1e9` 下放大到 1e-1，会把 0.5 的舍入下界污染成 0.502。改用 `Fraction` 后
   max abs err 回落到 0.499998。
