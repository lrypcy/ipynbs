# parallel_drafting：并行草稿与自适应验证的五个合成探针

对应文章：[《投机解码（09）：并行草稿与自适应验证——从「把草稿变准」到「把验证变省」》](https://lrypcy.github.io/2026/11/17/specdec-09-parallel-drafting-and-adaptive-verification/)
（`lrypcy.github.io` 推理服务分类，specdec 系列第 9 篇）。

## 这份脚本回答什么

2026 年的投机解码主线已经不是「再训一个更准的草稿器」，而是把草稿生成从逐 token 串行
改成一次前向出整块，并让运行时决定验证多少、接受什么。这组探针把五个论断放到数字上：

| # | 检查内容 | 结论 |
| --- | ---: | --- |
| 1 | 用 Red Hat 公布的 P-EAGLE 逐位置接受率反算平均接受长度 | `1 + Σ a_i = 3.042`，与官方 `Avg Length = 3.044` 差 0.002；相邻比值均值 **0.6472**、标准差 0.0092；常数 α 模型把每轮产出**高估 18.00%** |
| 2 | 草稿成本从 `γ·c` 换成常数 `c_b` 后收益曲面怎么变 | `γ*` 从 **3 → 7**，峰值 `S*` 从 **1.7973 → 2.2507**；`γ` 由 8 拉到 16 的跌幅从 **29.41% → 9.69%**；验证侧仍有 0.02 的增量，跌幅不为零 |
| 3 | 八节点候选树的祖先掩码 | 24 个可见元、下三角、兄弟分支互不可见，与对照矩阵**逐格一致** |
| 4 | 置信度调度只截断候选前缀时，输出分布是否仍等于目标分布 | 20 万轮蒙特卡洛：`TV(γ=2, p) = 0.00162`、`TV(γ=4, p) = 0.00137`；截断只把每轮产出从 **4.0934 → 2.7113**，不改分布 |
| 5 | margin 接受规则放宽后的分布偏差 | `τ=1` 时 `TV=0`；`τ=0.98` 时 `TV=0.19600`，`τ=0.92` 时反而降到 `0.05050`——放行集合扩大后偏差**不单调** |

第 1 组的输入是公开的一手数字：Red Hat Developer《Speeding up LLM inference with P-EAGLE
in vLLM Speculators》（2026-09-03）里 P-EAGLE 草稿模型的逐位置接受率表。第 2、4、5 组是
**合成探针**，用构造真值反算，不是任何模型的实测性能。

## 五组的关键数字（回填正文用）

```text
组 1：官方 Avg Length 3.044 / 反算 3.042 / 比值均值 0.6472 / 常数 α 高估 18.00%
组 2：γ* 串行 3 → 并行 7；S* 1.7973 → 2.2507；γ 8→16 跌幅 29.41% → 9.69%
组 3：祖先掩码 24 个非零元，下三角，与对照矩阵逐格一致
组 4：TV 0.00162 / 0.00137；每轮产出 2.7113 / 4.0934
组 5：TV 0.00000 → 0.19600 → 0.05050（τ = 1.00 / 0.98 / 0.92）
总计 23/23 条断言通过
```

## 一句话结论

并行草稿解耦的是**草稿生成成本**，不是验证成本；置信度调度截断的是**候选前缀长度**，
不是接受规则，所以无损性照旧；真正放弃分布正确性的是 margin 一类有损验证规则，
而它的偏差也不随阈值单调变化。
