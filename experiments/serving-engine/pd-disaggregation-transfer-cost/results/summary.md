==============================================================================
组 2：NIXL KV cache 租约（lease + heartbeat）状态机
==============================================================================
参数取自 vLLM 设计文档 nixl_kv_cache_lease.md 的默认值：
  初始租约 30s，心跳间隔 lease//6 ≈ 5s，每次续租 lease*2/3 ≈ 20s

场景                          设计                 心跳数    驻留 (s)    白占 (s)
A 健康：排队 100s 后传输            lease+hb            21     102.5       0.0
B 崩溃：D 在 t=10s 死掉           lease+hb             2      27.0      17.0
C 过载：心跳间隔 4.8s，排队 120s      lease+hb            26     122.5       0.0
D 旧设计：单一 480s 超时，D 崩溃       single-timeout       0     480.0     480.0

[自校验]
  1. 健康场景：传输完成即释放，心跳 21 次 = 覆盖 100s 等待所需
  2. 崩溃场景：最后心跳 t=7s → t=27.0s 回收；旧设计要等 480s，加速 17.8x
  3. 过载场景（间隔 4.8s）：租约仍活到传输完成
  4. 设计不变量：续租 20s > 心跳间隔 5s，单次心跳丢失仍可撑 15s
  5. 心跳按 (D, P) 配对批量发送，成本与在飞请求数无关

==============================================================================
结论
==============================================================================
组 1：传输与重算的时间比与 prompt 长度无关，只由「模型每 token KV 字节数」
      与「链路带宽 / 激活参数量」决定。BW*：Llama-3-8B 4.04 GB/s、
      Qwen3-32B 1.98、Llama-3-70B 1.15、DeepSeek-V3(MLA) 0.47。
      同一模型下，链路带宽每翻 10 倍，传输优势就扩大 10 倍；
      10GbE TCP（1.25 GB/s）上 8B 仍要重算（慢 3.2x），70B 已反超（0.92x）。
组 2：短租约 + 心跳把「D 崩溃后白占 KV」从 480s 压到 27s，
      同时不误杀健康但排队的请求 —— 单超时无法同时满足两者。
