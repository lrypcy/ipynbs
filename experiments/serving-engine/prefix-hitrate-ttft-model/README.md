# prefix-hitrate-ttft-model：命中率 → TTFT 的一阶模型核验

对应文章：[推理引擎（06）：benchmark 交叉验证](https://lrypcy.github.io/2026/10/18/serving-06-benchmark-cross-validation/)
（`lrypcy.github.io` 推理服务分类，serving 系列第 6 篇）。

## 这份脚本回答什么

SGLang v0.5.20 release notes（PR #34565，**厂商自报**）称：DeepSeek-V4-Flash +
共享 system prompt 下，token 命中率 43.8% → 60.8%，mean TTFT 1.57s → 1.07s。
随之流传开一句口诀：「命中率每 +10pp，TTFT 约降 19%」。

这份脚本不复现那个 benchmark（没有 H100），只做两件事：

1. **核验上报数字内部是否自洽**：把两点代进一阶模型
   $$\mathrm{TTFT}(h) = (1-h)\,P$$（命中部分零成本、未命中部分付全额 prefill），
   分别反解 $$P$$ 再互相预测，看残差；
2. **把「每 +10pp 降 19%」从模型里推出来**，说明它是区间中点的瞬时斜率、
   随命中率变化，不是常数 —— 口诀背下来会高估低命中率区的收益、低估高命中率区的收益。

顺带用同款直线模型拟合 v0.4 cache-aware LB 的两个吞吐点
（命中率 20% → 75%，82,665 → 158,596 tok/s），并明确标注：
**单请求 TTFT 斜率与聚合吞吐斜率量纲不同，不能互相换算。**

纯 Python / CPU、确定性输出。

## 如何运行

```bash
python3 run.py              # 跑两组，打印表格
python3 run.py --selftest   # 只跑断言（静默通过），适合挂 CI
```

## 两组检查与结论

| # | 检查内容 | 结论 |
| --- | --- | --- |
| 1 | 两点反解 $$P$$ 互相预测 | 前点反解 $$P=2.7936\,s$$、后点 $$P=2.7296\,s$$，**相差 2.32%**；平均 $$P=2.7616\,s$$ 下两点复现误差 <3%。一阶模型与上报数字**自洽** |
| 1b | 「每 +10pp 降幅」随 $$h$$ 的变化 | $$h=20\%$$ 时 12.5%、$$h=43.8\%$$ 时 17.8%、$$h=60\%$$ 时 25.0%、$$h=80\%$$ 时 50.0% —— **不是常数**；区间中点 21.0%，与流传「约 19%」量级一致 |
| 2 | 吞吐直线模型拟合 LB 两点 | $$k=2.5077$$、$$\mathrm{base}=55{,}054\ \mathrm{tok/s}$$，精确复现两点；中点瞬时斜率每 +10pp **+11.4%**（区间平均粗估 +14%，量级一致），且随 $$h$$ 增大而减小 |

**一句话结论**：上报的命中率 → TTFT 数字在一阶模型下自洽，但它给出的
「每 +10pp 降 19%」只是区间中点的斜率；真正的收益曲线是
$$\mathrm{TTFT}(h)=(1-h)P$$ —— 命中率从 20% 爬到 60% 的收益，
远大于从 60% 爬到 100%。

完整输出见 [`results/summary.md`](results/summary.md)。

## 哪些结论是这份脚本**没有**主张的

- **不是对 benchmark 的复现**。复现需要同硬件（H100）、同模型
  （DeepSeek-V4-Flash）、同负载；脚本只用上报的两个点做模型拟合，
  验证的是**内部自洽性**，不是真实性。
- 一阶模型 $$\mathrm{TTFT}=(1-h)P$$ 假设命中部分的 prefill 成本为零、
  未命中部分成本恒定。真实系统里命中块也有寻址开销、未命中部分的
  批处理会摊薄单位成本，所以模型是**下界估计的简化**。
- 组 2 的两个吞吐点来自**不同发布、不同负载**（8×A100 平衡共享前缀），
  与组 1 的 TTFT 点（DeepSeek-V4-Flash）没有任何关系；
  摆在一起只为说明「两条斜率量纲不同」。
- 没有建模 radix 树维护开销（低命中率时它是净负担，见文章 §6 的
  Issue #2558 证据）。
