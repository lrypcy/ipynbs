【第 2 组】重建掩码 vs 跳过的算力（D=64，BS=128，N=8192，L=32 层）
  单次重建相对「一次完整注意力」的成本：
    κ=1（纯比较）        0.003906  =  0.391%
    κ=4（带算术）        0.015625  =  1.562%

  摊销方式                单次重建占一层注意力   占整个前向（32 层）
    每步建一次、32 层复用   0.0122%           0.00038%
    每层各建一次            0.391%            0.391%
    每步建一次、32 层复用   0.0488%           0.00153%
    每层各建一次            1.562%            1.562%

  → break-even：只要掩码稀疏度让跳过的算力 > 重建成本，就划算。
    每层重建的阈值 ≈ κ/(4D) = 0.391% ~ 1.562% 的块被跳过。
    也就是说：**纯 FLOPs 口径下，每层重建几乎总是划算的**（阈值不到 2%）。
    真实成本不在 FLOPs，而在三处：物化的 bool 峰值显存、独立的 kernel 序列、
    以及动态 shape 触发的重编译。这正是官方 FAQ 把「每层重建」列为最难场景的原因。

  稀疏度收益 vs 每层重建代价（κ=4）：
    掩码            块级稀疏度(跳过比例)   省下算力     扣掉重建后净收益
    causal            46.9%              46.9%       +45.3%
    sliding w=512     72.7%              72.7%       +71.1%
    document          74.2%              74.2%       +72.7%

【第 3 组】确定性 dQ：同一组部分和，换顺序就换结果
  query 块 8 × KV 块 16，块大小 4，float32
  |升序串行 − 降序串行|               = 7.153e-07
  64 个随机顺序相对升序的最大偏差     = 1.192e-06（均值 6.049e-07）
  |升序串行 − 按 rank_asc 累加|       = 0.000e+00   ← 逐位一致
  |降序串行 − 按 rank_spt 累加|       = 0.000e+00   ← 逐位一致
  结论：rank 表把「谁先写」提前定死，累加顺序不再取决于 SM 的到达次序；
        dq_kv_order=True 只是把顺序反过来（SPT），两种都是确定的，只是基准不同。
