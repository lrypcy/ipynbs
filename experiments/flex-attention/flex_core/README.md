# flex_core：FlexAttention 编程模型的数值验证

对应文章：[《FlexAttention（01）：把注意力变体编译成一个 FlashAttention 内核》]
（`lrypcy.github.io`，编译器技术分类，FlexAttention 系列第 1 篇）。

## 这份脚本回答什么

FlexAttention 的两篇官方材料（arXiv:2412.05496 与 PyTorch 两篇博客）把「易用」和「够快」
讲得很清楚，但把两件真正重要的事留给了读者自己想：

1. **为什么一个「随便写的」逐点函数可以被塞进 online softmax 的流式循环里还不出错**；
2. **这个自由度的边界到底在哪**——什么样的东西无论怎么编译都写不出来。

这两件事纯粹是数学的，不需要 GPU。这份脚本用**纯 numpy / CPU** 把它们摆到数字上，
每条都做「构造真值 ↔ 流计算」或「解析真值 ↔ 数值反算」自校验。

## 如何运行

```bash
python3 run.py              # 跑全部七组，打印表格
python3 run.py 1 3          # 只跑第 1、3 组
python3 run.py --selftest   # 只跑断言（静默），适合挂 CI
```

依赖只有 numpy，固定 `seed = 20261017`，逐位可复现。共 27 条断言，全过。

## 七组检查与结论

| # | 检查内容 | 结论 |
| ---:|:---|:---|
| 1 | online softmax × 六种 `score_mod`（noop / causal / alibi / softcap / rel_bias / causal+alibi） | 流式（分块 32）与一次性材料化整矩阵的最大相对差 **1.776e-15**，lse 同量级 —— 那条 $$lpha$$-重标定循环对任意逐点修正都成立 |
| 2 | base-2 换底与 logsumexp 的口径 | `RCP_LN2 = 1/ln2 = 1.44269504`；内部算的是 $$\log_2\sum\exp_2(\cdot)$$，返回前乘 $$\ln 2$$ 换回自然对数。三条路径（自然 log / base-2 换算 / 定义式）两两相差 ≤ 8.882e-16 |
| 3 | 运行最大值 $$m_i$$ 为什么必须取在**修正之后**的分数上 | 数学上取哪一侧都对（bias=+80 时两侧都是 1e-15 级），但真实求过的 $$\log_2$$ 指数上界是 **115.42 vs 0.00**，差值恰好等于 $$\text{bias}/\ln 2$$。 bias=+160 时差值 230.83，超过 float32 的 $$2^{127}$$ 溢出阈值 —— 取修正前会直接炸掉 |
| 4 | 表达力边界：依赖整行统计量的 mod | 逐点 mod（soft-cap）流式逐位可复现（4.996e-16）；依赖行均值的 mod 差 **4.365e-02**，且部分行均值要到最后一块才收敛（偏差序列 0.125398 → 0.058475 → 0.034071 → 0.000000）。重标定只改得了分母，改不了已经混进 `acc` 的分子 |
| 5 | BlockMask 的两笔账 | N=512 / BS=64：causal 保留 36/64 块（full 28 + partial 8），元素密度 50.1% 但块级密度 56.2% —— **粒度是有损的**。 N=32768 / BS=128：稠密 bool 掩码 1073.74 MB，BlockMask 元数据 0.2632 MB（4080×）；BS 提到 1024 变 0.0042 MB（254200×） |
| 6 | `and_mask` / `or_mask` 的逻辑融合 | 与手写掩码逐元素一致（差异 0 个元素）。注意 `or(prefix, causal)` 得到的是「前缀区内双向 + 其余因果」，**不是**「前 N 行全可见」 |
| 7 | PagedAttention 的 physical → logical 索引转换 | 物理布局乱序存放 + 反查后套用原 `mask_mod`，输出与连续逻辑布局相差 **1.877e-16**。反查是 $$O(1)$$：`physical_kv_block = kv_idx // PAGE`，余数补回去 |

## 哪些结论是这份脚本**没有**主张的

- **不涉及任何性能**。第 1、2、4、7 组验证的是**语义等价**，不含访存、带宽、融合、
  自动调优；第 5 组只算元数据的字节数与跳过的块数，不预测 kernel 时间。
- **第 3 组不主张「取修正前一定出错」**。它主张的是：数学上等价（softmax 对参考值的选择
  是不变的），但溢出裕度会被 mod 的量级吃掉。真正在 float32 上炸掉与否还取决于具体的
  数据量级与 $$s_m$$ 尺度。
- **第 5 组的显存账按 int32 索引、B=H=1 计算**。实际 `BlockMask` 在部分分支上还会保存
  `full_kv_*`、`q_*`（反向用）以及 `dq_write_order` 等派生元数据，总量会比这里高一截；
  这里算的是「相对稠密掩码」的下界。
- **第 7 组只是把页表打乱成随机排列**（验证索引转换本身，不是真正的变长请求批处理调度）。它验证的是
  索引转换这个函数，不是 vLLM 的调度器。
